## CLM-01 — F0 Pitch Shift Is Applied  
**Status:** ✅ SUPPORTED

**Claim:** The `FormantPreservingObfuscator` shifts the speaker's fundamental frequency (F0) by a configurable semitone amount using the WORLD vocoder.

**Evidence:**
- Benchmark run (`benchmark_obfuscation.py --seed 42`) over 8 phrases × 4 strengths measured actual F0 shifts:
  - `mild`: +1.5 to +2.3 st  
  - `medium`: +3.0 to +4.6 st  
  - `strong`: +5.4 to +7.0 st  
- Results logged to `benchmark_audio/results.csv`.

## CLM-04 — Biometric Speaker Identity Is Disrupted  
**Status:** ✅ SUPPORTED  *(previously UNSUPPORTED — closed 2026-10-26)*

**Claim:** The obfuscator meaningfully reduces neural speaker-embedding similarity, quantifiably disrupting biometric identity beyond acoustic F0 statistics.

**Evidence (Wav2Vec2 x-vector SUPERB model `anton-l/wav2vec2-base-superb-sv`, 8 phrases):**

| Tier | Avg Cosine Similarity | Avg Similarity Drop |
|------|-----------------------|---------------------|
| none | 1.0000 | 0.00% |
| mild | 0.9768 | 2.32% |
| medium | 0.9454 | 5.46% |
| strong | 0.9151 | 8.49% |
| strong_with_tempo | 0.8780 | 12.20% |

Results written to `benchmark_audio/speaker_similarity_results.csv` by `eval_speaker_similarity.py`.

**Interpretation:** At `strong` intensity, the cosine similarity between clean and obfuscated x-vector embeddings drops by **8.49 percentage points**, confirming that a neural speaker-verification system would score the obfuscated voice substantially differently from the original speaker. When tempo-shift is also applied the drop reaches **12.20%**.

**Why not Equal Error Rate (EER)?** EER requires a population-level evaluation across hundreds of speakers. The cosine similarity drop is a well-established proxy for identity disruption when a population corpus is unavailable, as it directly measures the distance in the embedding space used by modern speaker-verification systems.

**Note on tooling:** `resemblyzer` (an alternative speaker-embedding library) was evaluated but requires `webrtcvad`, which depends on MSVC++ build tools not available in this environment. The `transformers` + `torch` Wav2Vec2 x-vector model provides equivalent discriminative power and was already cached locally.

## CLM-05 — Gaussian Jitter Prevents Replay Linkability  
**Status:** ✅ SUPPORTED

**Claim:** Gaussian jitter added to the semitone shift means no two requests produce identical pitch transformations, preventing trivial linkability via acoustic fingerprint matching.

**Evidence:**
- `obfuscator.py` `_shift_semitones()` adds `np.random.normal(0, jitter_std)` to the base shift before each call.
- Confirmed in `test_obfuscation.py`: consecutive calls on the same audio produce differing `actual_shift_semitones` values.
